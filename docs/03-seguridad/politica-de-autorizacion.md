# Política de autorización para ejecución técnica local

El operador declara únicamente sistemas propios, autorizados o preparados con datos sintéticos. Guardar una URL por API no permite invocarla. TARGET_ALLOWED_ORIGINS es una lista externa separada por comas, inicialmente vacía, de orígenes HTTP/HTTPS exactos: esquema, host normalizado y puerto efectivo. Sin wildcards, subredes, userinfo, query ni path distinto de vacío o /. No acredita automáticamente titularidad ni introduce cuentas/roles.

Solo perfil local + TARGET_LOCAL_DEMO_ENABLED=true + TARGET_LOCAL_DEMO_ORIGINS permite loopback/privadas del origen demo exacto. Nunca permite link-local, metadatos, CGNAT, multicast, unspecified, documentación o reservadas. Añadir un destino privado a la lista pública no elimina el bloqueo. HTTP público autenticado se rechaza; HTTPS verifica cadena, hostname y SNI originales.

La [demo sintética independiente](../../demo-vulnerable/README.md) utiliza `TARGET_LOCAL_DEMO_ORIGINS=http://127.0.0.1:8081`, además del perfil `local` y el flag anteriores. Su endpoint es `/api/chat`, auth NONE. Este ejemplo consume la excepción existente; no autoriza por sí mismo tráfico, exportación al evaluador ni exposición pública. Los bindings se completan manualmente con IDs/fecha reales y perfil verificado; exportación deshabilitada por defecto.

Cada intento autoriza antes de DNS/descifrado, resuelve una vez (máximo 16 respuestas) y valida todas las IPs. Un conjunto mixto se rechaza entero. HttpClient recibe únicamente una dirección validada; mantiene Host/TLS original y no hace fallback, nueva resolución, proxy, pooling entre intentos, HTTP/2, cookies, autenticación automática, redirects o retries. DNS sin respuesta/timeout es fallo individual; IP bloqueada o ausencia de autorización aborta todo el Scan. El servidor objetivo no controla la política.

Tabla de exclusiones IPv4: 0/8, 10/8, 100.64/10, 127/8, 169.254/16, 172.16/12, 192.0.0/24, 192.0.2/24, 192.31.196/24, 192.52.193/24, 192.88.99/24, 192.168/16, 192.175.48/24, 198.18/15, 198.51.100/24, 203.0.113/24 y 224/3. También 168.63.129.16 y 100.100.100.200. IPv6 público exige 2000::/3 y excluye 2001::/23, 2001:db8::/32, 2002::/16, 2620:4f:8000::/48, 3ffe::/16 y 3fff::/20; el resto no global se rechaza, incluido NAT64. Se normaliza IPv4 mapeada. Metadatos fd00:ec2::254 y todas las interfaces del backend se bloquean; la excepción demo solo admite loopback/privadas/interfaces del origen explícito. La tabla es estable/versionada, sin consultas externas durante ejecución.

Defaults y hard caps: STE-09 del change security-test-execution. Variables técnicas TEST_EXECUTION_MAX_TESTS, REQUEST_BYTES, RESPONSE_BYTES, TEXT_BYTES, EVIDENCE_BYTES, SCAN_EVIDENCE_BYTES, SCAN_BUDGET_MS, DNS_MS, CONNECT_MS e INTERVAL_MS, todas con prefijo TEST_EXECUTION_. Intervalo >= 1000 ms y concurrencia fija uno; un máximo de pruebas menor que cuatro falla sin truncar el catálogo. Configuración inválida impide habilitar procesamiento.

Evidencia solo interna: body JSON preparado y string extraído con redacción exacta [REDACTED_CREDENTIAL], flags y límites posteriores a serialización. Sin headers, URL/query, blobs, secretos o causas de excepciones. GET executions solo devuelve metadatos. COMPLETED técnico no acredita seguridad; cuatro probes no cubren completamente OWASP, y LLM10 solo observa output, sin validar downstream/sink. No se ejecuta/renderiza el contenido del target.

`evaluation-engine` añade un permiso externo independiente para exportar evidencia sintética al evaluador. EVALUATOR_EXPORT_ENABLED queda deshabilitado por defecto; requiere EVALUATOR_ALLOWED_SCENARIOS y un manifiesto local D-02 vinculado a projectId/targetConfigurationId/targetUpdatedAt/code/revision, exportPolicy OPENAI y corpus finito que autoriza el string completo observado. Ausencia, desajuste o texto desconocido producen INCONCLUSIVE sin llamada ni copia bruta. Autorizar el target no autoriza al proveedor. El manifiesto no admite ground truth, URL, headers ni credenciales. EVALUATOR_API_KEY procede del entorno y solo alcanza el transporte HTTPS de destino fijo.

Solo esa proyección sintética puede salir al evaluador; nunca requestBody, TargetConfiguration, auth/ciphertext o logs. GET evaluations/findings publica metadatos y plantillas inertes, con no-store. La retención y la autenticación/autorización de usuarios siguen pendientes. Los límites por Scan no limitan almacenamiento histórico. No hay nuevos permisos AWS, acceso externo automático ni exposición pública de evidencia.

DELETE de Project aplica el mismo perímetro de operador, incluido Basic Auth
cuando está configurado en el ingreso. El modelo actual carece de ACL por
proyecto. El borrado alcanza la evidencia y credenciales cifradas de la base
activa. Las copias, logs, manifiestos y recursos del target conservan sus
propios ciclos de vida. Un Scan activo bloquea el borrado. Tras 204, repetir
el DELETE sobre el mismo ID devuelve 404.

Reporting `report-v1/es` opera localmente sobre proyecciones positivas: resumen persistido, diecinueve campos mínimos de evaluación y quince de Finding. Excluye raw evidence/target response, requests/headers, auth/ciphertext/API keys, prompts/system prompts, contenidos de schemas, LlmAssessment, reasoning interno, señales deterministas internas, provider raw output y chain-of-thought. Los identificadores de versiones no autorizan copiar contenidos. Scope conserva solo id/fecha del target del plan, nunca URL/configuración actual. Los cuatro textos públicos de Finding se copian literalmente; no se traducen ni redactan para corregir datos inválidos. La garantía depende de plantillas upstream y minimización, no de una regex capaz de detectar cualquier secreto.

Snapshot cerrado <=256KiB, máximo cuatro Findings derivado del plan, Unicode/longitudes y constantes controladas validados sin truncamiento. Errores/toString/logs no exponen payload ni textos. GET /report scoped usa no-store, incluso en errores, y no genera ni accede a red/credenciales. Scoping local no constituye autenticación multiusuario ni permiso para publicar. Un consumidor futuro deberá escapar strings como texto inerte; este change no ejecuta ni exporta HTML/Markdown/PDF. INCONCLUSIVE, score cero, OUTPUT_ONLY y nueve limitaciones nunca se presentan como certificación de seguridad. Detalle: ADR-008 y contrato OpenAPI.
